Instalação

Base, ISOs, VM com 3D, bootstrap, opções e kickstart.

7 min de leituraVer no GitHub

O msbos é instalado sobre um Fedora já existente (rota C): não há ISO própria. O install.sh roda sete etapas base idempotentes (+ a etapa opt-in de zoom e duas de migração, no-op em instalação nova), instala os pacotes, configura os serviços e aplica os ajustes. A troca do shell do Plasma pelo niri/Noctalia só vale depois do reboot.

Antes de começar

  • Fedora 44 ou 45, x86_64, já instalado e com a rede funcionando.
  • Acesso a sudo e o usuário que vai receber a configuração (padrão: quem chamou o sudo).
  • Espaço em disco e tempo proporcionais à quantidade de pacotes (a primeira instalação baixa bastante coisa; as etapas seguintes são incrementais).
  • Faça backup do que importa. O instalador cria backups .msbos-bak dos arquivos que sobrescreve, mas isso não substitui um backup seu.

A base recomendada é o Fedora KDE: o script remove apenas o shell do Plasma (desktop, workspace e Plasma Login Manager) e mantém os apps do KDE. Uma instalação mínima do Fedora também funciona e gera um sistema ainda mais enxuto; nesse caso o script adiciona o stack e os apps KDE que faltarem.

Espelhos diretos (troque 44 pela versão desejada; a lista completa está em https://mirrors.fedoraproject.org):

  • KDE: https://download.fedoraproject.org/pub/fedora/linux/releases/44/KDE/x86_64/iso/
  • Everything: https://download.fedoraproject.org/pub/fedora/linux/releases/44/Everything/x86_64/iso/

Confira o checksum com os arquivos -CHECKSUM e, se possível, a assinatura OpenPGP do Fedora antes de instalar.

Testar em uma VM

O niri rejeita renderização por software (llvmpipe) por design. Uma VM precisa de virtio-gpu com aceleração 3D e GL no Spice; sem isso a sessão fica em tela preta. O qxl, muito comum em VMs, não funciona com o niri.

bash
virt-install --name msbos --memory 4096 --vcpus 3 --disk size=25 \
  --cdrom /caminho/Fedora-KDE-Desktop-Live-44.x86_64.iso \
  --os-variant fedora-unknown \
  --graphics spice,gl=on --video virtio,accel3d=yes

Se a VM já existe, veja VM com tela preta para corrigir vídeo/GL e os contornos de artefatos do QEMU.

Instalar sem clonar o repositório

O bootstrap.sh baixa o repositório como .tar.gz, extrai em um diretório temporário e chama o install.sh. Não precisa de git.

Salve o bootstrap em um arquivo antes de executar: assim os prompts interativos do install.sh continuam lendo o terminal.

bash
curl -fsSL https://raw.githubusercontent.com/marcos2872/msbos/main/bootstrap.sh -o /tmp/msbos.sh

sudo bash /tmp/msbos.sh --dry-run   # simula tudo (recomendado na 1ª vez)
sudo bash /tmp/msbos.sh             # instala de verdade

Para fixar uma branch, tag ou commit:

bash
sudo env MSBOS_REF=SEU_TAG_OU_COMMIT bash /tmp/msbos.sh --yes

Instalação não interativa (VM descartável/CI):

bash
curl -fsSL https://raw.githubusercontent.com/marcos2872/msbos/main/bootstrap.sh \
  | sudo bash -s -- --yes

Variáveis aceitas pelo bootstrap:

VariávelPadrãoEfeito
MSBOS_REFmainBranch, tag ou commit a baixar
MSBOS_REPOmarcos2872/msbosRepositório alternativo (owner/repo)
MSBOS_URL—URL completa do .tar.gz; sobrepõe REPO/REF
MSBOS_KEEP01 mantém o diretório temporário para depuração

O bootstrap aceita todas as opções do install.sh e repassa os argumentos.

Instalar com clone (desenvolvimento)

bash
git clone https://github.com/marcos2872/msbos.git
cd msbos

./install.sh --dry-run   # simula tudo, sem alterar nada
./install.sh             # instala de verdade

Ao rodar sem root e sem --dry-run, o install.sh se reexecuta com sudo, preservando as variáveis da instalação.

Opções do install.sh

OpçãoEfeito
--dry-runSimula tudo: não instala, não remove, não escreve e não acessa a rede
--yes, -yAutoriza operações destrutivas (remoção do shell do Plasma e limpeza de artefatos antigos) sem perguntar
--no-greeterNão adiciona o repositório Terra; usa o greeter padrão do greetd
--user NOMEUsuário-alvo da configuração (padrão: quem chamou o sudo)
--gpu-profile PForça auto, intel, amd, nvidia, hybrid ou none
--skip-removeNunca remove pacotes; apenas instala e ajusta serviços
--with-niri-zoomInstala o niri com zoom por output (fork opt-in do PR niri#3246; compila em podman e usa /usr/local/bin/niri)
-h, --helpMostra a ajuda extraída do cabeçalho do install.sh

As mesmas opções valem para o bootstrap, por exemplo sudo bash /tmp/msbos.sh --gpu-profile nvidia.

O que acontece durante a instalação

O install.sh descobre scripts/[0-9][0-9]-*.sh em ordem e executa:

EtapaResumo
10-gpu.shDetecta Intel/AMD/NVIDIA (inclusive híbridos) e instala o driver adequado
20-stack.shInstala niri, Noctalia, greetd, áudio, utilitários, apps e agenda a remoção do shell do Plasma
25-devtools.shgcc/make, Rust, Node via nvm, pnpm/yarn e virtualização (KVM/libvirt)
30-services.shColoca o greetd no boot, mascara outros DMs e desativa daemons dispensáveis
40-tuning.shzram, sysctl de memória, compressão btrfs, governor e oomd
50-configs.shConfigura niri, Noctalia, Breeze Dark, greetd/PAM, wallpapers, Zed, zsh e apps padrão
60-agent-skill.shInstala o helper privilegiado (polkit), as listas de root e a skill msbos para agentes de IA

Detalhes de cada etapa: Arquitetura e etapas.

Nada é parado na sessão atual. O Plasma continua funcionando até o reboot; a remoção do shell do Plasma é agendada para o próximo boot, antes do login, via msbos-remove-plasma.service. Isso evita derrubar a sessão no meio da transação do dnf.

Cada etapa concluída deixa um marcador em /var/lib/msbos/steps/. Se uma etapa falhar, o instalador mostra o código de erro, o histórico e como retomar.

Zoom do niri (opcional)

O niri do Fedora não tem zoom. O msbos traz um fork opcional com zoom de acessibilidade por output, desligado por padrão: a etapa 55-niri-zoom.sh só roda quando a instalação é chamada com --with-niri-zoom.

bash
sudo bash /tmp/msbos.sh --with-niri-zoom   # instalando pelo bootstrap
./install.sh --with-niri-zoom              # instalando pelo clone

Num sistema que já tem o msbos dá para rodar só essa etapa, sem repetir as outras:

bash
sudo env WITH_NIRI_ZOOM=1 bash scripts/55-niri-zoom.sh

A etapa:

  • compila o commit fixado do PR niri#3246 + o patch local do msbos num container Fedora 44 — precisa de podman e de rede, e leva alguns minutos;
  • instala o binário em /usr/local/bin/niri; o /usr/bin/niri do pacote fica intacto;
  • cria ~/.config/niri/zoom.kdl e acrescenta include "zoom.kdl" ao config.kdl do usuário, com backup e validação (se o config ficar inválido, o backup volta);
  • instala os helpers msbos-zoom-reset e msbos-niri-zoom-remove.

A etapa é idempotente: o marcador /usr/local/share/msbos/niri-zoom.commit guarda o commit, o patch e o sha256 do binário, então repetir a instalação com o mesmo commit não recompila. Em --dry-run nada disso acontece — a etapa simula sem rede, sem podman e sem compilar.

Vale no próximo login. A sessão em execução continua no niri antigo; saia e entre de novo (ou reinicie). Para conferir que o binário novo está no lugar:

bash
command -v niri                 # deve responder /usr/local/bin/niri
cat /usr/local/share/msbos/niri-zoom.commit

Os atalhos estão em Uso diário. Para remover o fork e voltar ao niri do pacote:

bash
sudo msbos-niri-zoom-remove

Instalação desatendida (kickstart + primeiro boot)

Não execute o install.sh diretamente no %post. O %post roda no chroot do sistema instalado, sem systemd como PID 1, e o msbos precisa de um sistema já inicializado (systemctl daemon-reload, runuser, dconf/gsettings). O caminho certo é um serviço de primeiro boot que rode o bootstrap depois que o sistema subir — é o que o modo --firstboot prepara (no %post, como root):

bash
bash bootstrap.sh --firstboot --user NOME

Esse comando instala três arquivos e não instala o desktop agora:

ArquivoPapel
/usr/local/libexec/msbos-firstboothelper que roda o bootstrap com --yes --user NOME
/etc/systemd/system/msbos-firstboot.serviceoneshot habilitada para o primeiro boot
/etc/msbos/firstboot.confTARGET_USER (obrigatório), MSBOS_REF e MSBOS_REPO (opcionais)

No primeiro boot a unit baixa e executa o install.sh (teto de 2 h). Se der certo, grava o marcador /var/lib/msbos/firstboot.done e se desabilita — o login seguinte já é o desktop do msbos, com a remoção do shell do Plasma agendada como sempre. Se falhar, ela tenta de novo nos próximos boots e desiste depois de 3 tentativas (contador em /var/lib/msbos/firstboot.attempts). Ela nunca reinicia a máquina.

Acompanhe e confira:

bash
journalctl -u msbos-firstboot -b        # esta tentativa
journalctl -u msbos-firstboot -b -1     # tentativa anterior, se a atual falhou
ls /var/lib/msbos/steps/                # etapas concluídas pelo install.sh

kickstart/msbos-firstboot.ks traz um %post pronto para colar no seu kickstart (ajuste o usuário). Em instalação normal, com o sistema já no ar, não use --firstboot: rode o bootstrap com --yes como sempre.

Depois de instalar

Reinicie:

bash
sudo reboot

No próximo boot, a tela do greetd deve aparecer com a sessão niri disponível. No primeiro login, o autostart msbos-greeter-sync sincroniza a aparência com a tela de login; o wallpaper aparece no próximo logout/reboot.

Verificações úteis no sistema instalado:

bash
msbos-doctor                 # diagnóstico completo (somente leitura)
systemctl status greetd          # display manager
journalctl -u greetd -n 30       # log do login
free -h ; zramctl                # swap comprimido ativo
ps aux --sort=-rss | head -12    # maiores consumidores de RAM

O shell padrão passa a ser o zsh; o grupo libvirt só vale no próximo login. Se precisar repetir o sync da aparência com a tela de login depois de entrar:

bash
noctalia msg greeter-sync

Reexecutar ou retomar

As etapas são idempotentes; rodar de novo é seguro:

bash
sudo ./install.sh              # tudo, desde o início
sudo bash scripts/50-configs.sh  # só uma etapa
DRY_RUN=1 bash scripts/40-tuning.sh  # simular uma etapa sem root

O histórico fica em:

bash
ls /var/lib/msbos/steps/

Para restaurar um arquivo sobrescrito, procure o backup .msbos-bak ao lado do original. Configurações pessoais instaladas com install_file_once não são sobrescritas em uma reexecução; para voltar ao padrão, apague o arquivo e rode a etapa correspondente.
