Installation

Base, ISOs, VM with 3D, bootstrap, options and kickstart.

7 min readView on GitHub

msbos is installed on top of an existing Fedora (route C): there is no custom ISO. install.sh runs seven base idempotent steps (+ the opt-in zoom step and two migration steps, no-ops on a fresh install), installs packages, configures services and applies the tuning. Replacing the Plasma shell with niri/Noctalia only takes effect after a reboot.

Before you start

  • Fedora 44 or 45, x86_64, already installed with working network access.
  • sudo access and the user who will receive the configuration (default: whoever invoked sudo).
  • Disk space and time proportional to the number of packages (the first install downloads a lot; later runs are incremental).
  • Back up anything important. The installer creates .msbos-bak backups of files it overwrites, but that is not a replacement for your own backup.

The recommended base is Fedora KDE: the script removes only the Plasma shell (desktop, workspace and Plasma Login Manager) and keeps the KDE apps. A minimal Fedora install also works and produces an even leaner system; in that case the script adds the missing stack and KDE apps.

  • Everything: https://download.fedoraproject.org/pub/fedora/linux/releases/44/Everything/x86_64/iso/

Check the checksum against the -CHECKSUM files and, if possible, the Fedora OpenPGP signature before installing.

Testing in a VM

niri rejects software rendering (llvmpipe) by design. A VM needs virtio-gpu with 3D acceleration and GL on Spice; otherwise the session stays black. The qxl adapter, common in VMs, does not work with niri.

bash
virt-install --name msbos --memory 4096 --vcpus 3 --disk size=25 \
  --cdrom /path/to/Fedora-KDE-Desktop-Live-44.x86_64.iso \
  --os-variant fedora-unknown \
  --graphics spice,gl=on --video virtio,accel3d=yes

If the VM already exists, see Black screen or inverted cursor in a VM to fix video/GL and the QEMU artifact workarounds.

Install without cloning the repository

bootstrap.sh downloads the repository as a .tar.gz, extracts it to a temporary directory and calls install.sh. No git required.

Save the bootstrap to a file before running it: that way the interactive install.sh prompts keep reading from the terminal.

bash
curl -fsSL https://raw.githubusercontent.com/marcos2872/msbos/main/bootstrap.sh -o /tmp/msbos.sh

sudo bash /tmp/msbos.sh --dry-run   # simulate everything (recommended first)
sudo bash /tmp/msbos.sh             # install for real

Pin a branch, tag or commit:

bash
sudo env MSBOS_REF=YOUR_TAG_OR_COMMIT bash /tmp/msbos.sh --yes

Non-interactive install (throwaway VM/CI):

bash
curl -fsSL https://raw.githubusercontent.com/marcos2872/msbos/main/bootstrap.sh \
  | sudo bash -s -- --yes

Variables accepted by the bootstrap:

VariableDefaultEffect
MSBOS_REFmainBranch, tag or commit to download
MSBOS_REPOmarcos2872/msbosAlternative repository (owner/repo)
MSBOS_URL—Full .tar.gz URL; overrides REPO/REF
MSBOS_KEEP01 keeps the temporary directory for debugging

The bootstrap accepts every install.sh option and forwards the arguments.

Install with a clone (development)

bash
git clone https://github.com/marcos2872/msbos.git
cd msbos

./install.sh --dry-run   # simulate everything, change nothing
./install.sh             # install for real

When run without root and without --dry-run, install.sh re-executes itself with sudo, preserving the installation variables.

install.sh options

OptionEffect
--dry-runSimulates everything: installs nothing, removes nothing, writes nothing and does not access the network
--yes, -yAuthorizes destructive operations (Plasma shell removal and old-artifact cleanup) without asking
--no-greeterDoes not add the Terra repository; uses greetd's default greeter
--user NAMETarget user for the configuration (default: whoever invoked sudo)
--gpu-profile PForces auto, intel, amd, nvidia, hybrid or none
--skip-removeNever removes packages; only installs and adjusts services
--with-niri-zoomInstalls niri with per-output zoom (opt-in fork of PR niri#3246; builds in podman and uses /usr/local/bin/niri)
-h, --helpShows the help extracted from the install.sh header

The same options work with the bootstrap, for example sudo bash /tmp/msbos.sh --gpu-profile nvidia.

What happens during installation

install.sh discovers scripts/[0-9][0-9]-*.sh in order and runs:

StepSummary
10-gpu.shDetects Intel/AMD/NVIDIA (including hybrid setups) and installs the right driver
20-stack.shInstalls niri, Noctalia, greetd, audio, utilities, apps and schedules Plasma shell removal
25-devtools.shgcc/make, Rust, Node via nvm, pnpm/yarn and virtualization (KVM/libvirt)
30-services.shPuts greetd on boot, masks other display managers and disables unnecessary daemons
40-tuning.shzram, memory sysctls, btrfs compression, CPU governor and oomd
50-configs.shConfigures niri, Noctalia, Breeze Dark, greetd/PAM, wallpapers, Zed, zsh and default apps
60-agent-skill.shInstalls the privileged helper (polkit), the root lists and the msbos skill for AI agents

Details for each step: Architecture and steps.

Nothing is stopped in the current session. Plasma keeps working until reboot; the Plasma shell removal is scheduled for the next boot, before login, through msbos-remove-plasma.service. This avoids killing the session in the middle of a dnf transaction.

Each completed step leaves a marker in /var/lib/msbos/steps/. If a step fails, the installer prints the error code, the history and how to resume.

Niri zoom (optional)

The Fedora niri has no zoom. msbos ships an optional fork with per-output accessibility zoom, off by default: the 55-niri-zoom.sh step only runs when the install is called with --with-niri-zoom.

bash
sudo bash /tmp/msbos.sh --with-niri-zoom   # installing through the bootstrap
./install.sh --with-niri-zoom              # installing from a clone

On a system that already runs msbos you can run just this step, without repeating the others:

bash
sudo env WITH_NIRI_ZOOM=1 bash scripts/55-niri-zoom.sh

The step:

  • builds the pinned commit of PR niri#3246 + the local msbos patch in a Fedora 44 container — it needs podman and network, and takes a few minutes;
  • installs the binary at /usr/local/bin/niri; the package's /usr/bin/niri stays untouched;
  • creates ~/.config/niri/zoom.kdl and appends include "zoom.kdl" to the user's config.kdl, with a backup and validation (if the config becomes invalid, the backup is restored);
  • installs the msbos-zoom-reset and msbos-niri-zoom-remove helpers.

The step is idempotent: the /usr/local/share/msbos/niri-zoom.commit marker records the commit, the patch and the binary sha256, so re-running the install with the same commit does not rebuild. Under --dry-run none of that happens — the step simulates without network, podman or compilation.

It takes effect on the next login. The running session stays on the old niri; log out and back in (or reboot). To confirm the new binary is in place:

bash
command -v niri                 # should print /usr/local/bin/niri
cat /usr/local/share/msbos/niri-zoom.commit

The shortcuts are in Daily use. To remove the fork and go back to the package's niri:

bash
sudo msbos-niri-zoom-remove

Unattended install (kickstart + first boot)

Do not run install.sh directly from %post. %post runs inside the installed system's chroot without systemd as PID 1, and msbos needs a booted system (systemctl daemon-reload, runuser, dconf/gsettings). The right approach is a first-boot service that runs the bootstrap once the system is up — which is what the --firstboot mode sets up (inside %post, as root):

bash
bash bootstrap.sh --firstboot --user NAME

That command installs three files and does not install the desktop right away:

FileRole
/usr/local/libexec/msbos-firstboothelper that runs the bootstrap with --yes --user NAME
/etc/systemd/system/msbos-firstboot.serviceoneshot enabled for the first boot
/etc/msbos/firstboot.confTARGET_USER (required), MSBOS_REF and MSBOS_REPO (optional)

On the first boot the unit downloads and runs install.sh (capped at 2 h). On success it writes the /var/lib/msbos/firstboot.done marker and disables itself — the next login is already the msbos desktop, with the Plasma shell removal scheduled as usual. On failure it retries on the following boots and gives up after 3 attempts (counter in /var/lib/msbos/firstboot.attempts). It never reboots the machine.

Follow and inspect:

bash
journalctl -u msbos-firstboot -b        # this attempt
journalctl -u msbos-firstboot -b -1     # previous attempt, if the current one failed
ls /var/lib/msbos/steps/                # steps completed by install.sh

kickstart/msbos-firstboot.ks has a ready-to-paste %post (adjust the user). On a normal install, with the system already up, do not use --firstboot: run the bootstrap with --yes as usual.

After installation

Reboot:

bash
sudo reboot

On the next boot, the greetd screen should appear with the niri session available. On the first login, the msbos-greeter-sync autostart syncs the appearance with the login screen; the wallpaper shows up on the next logout/reboot.

Useful checks on the installed system:

bash
msbos-doctor                 # full diagnosis (read-only)
systemctl status greetd          # display manager
journalctl -u greetd -n 30       # login log
free -h ; zramctl                # compressed swap active
ps aux --sort=-rss | head -12    # top RAM consumers

The default shell becomes zsh; the libvirt group only applies on the next login. To repeat the appearance sync with the login screen after logging in:

bash
noctalia msg greeter-sync

Re-running or resuming

The steps are idempotent; running them again is safe:

bash
sudo ./install.sh                # everything, from the start
sudo bash scripts/50-configs.sh  # a single step
DRY_RUN=1 bash scripts/40-tuning.sh  # simulate one step without root

The history lives in:

bash
ls /var/lib/msbos/steps/

To restore an overwritten file, look for the .msbos-bak backup next to the original. Personal configurations installed with install_file_once are not overwritten on a re-run; to return to the default, delete the file and run the corresponding step.
