Daily use

niri shortcuts, Noctalia, theme, wallpapers and greeter.

7 min readView on GitHub

After rebooting, greetd presents the niri session. Noctalia v5 draws the bar, launcher, notifications, OSD and lock screen; KDE apps remain available and use Breeze Dark.

Niri zoom (optional)

With the install done using --with-niri-zoom, the compositor gets per-monitor accessibility zoom. To install it later on a system that already runs msbos, the step by step is in installation.

ShortcutAction
Super+Alt+scrollAdjusts zoom on the focused monitor
Super+Alt+= / Super+Alt+-Zoom in/out with the keyboard
Super+Alt+0Unlocks and resets to 1.0
Super+Alt+ZLocks/unlocks the focal point

The viewport anchors at the cursor and does not follow the mouse by itself. Hold Super and move the mouse to pan; when you release it, the zoom stays at the last point. Since Super+Alt+scroll also holds Super, the zoom follows the cursor during the gesture and stops when you let go.

To remove the fork and return to the package's niri:

bash
sudo msbos-niri-zoom-remove

Noctalia v5

Noctalia is the desktop shell: bar, launcher, notifications, OSD, control center, lock screen and wallpaper. The default look is Liquid Glass with the macOS palette: translucent top bar, half-height auto-hiding dock, glass panels and faster animations.

The two configuration layers

Noctalia v5 assembles its configuration in layers. Two matter in msbos:

LayerFileContentsWritten by
Style~/.config/noctalia/config.tomlTheme, palette, bar, dock, panels, animationsmsbos (installed once; you may edit)
State/GUI~/.local/state/noctalia/settings.tomlWidget lists, wallpaper, plugins, lock-screen geometry, persisted [dock]The Noctalia GUI

settings.toml is read last and wins key by key. So if an appearance change “does not stick”, there is almost always a duplicate key there. config.toml holds style; settings.toml holds what the GUI rewrites. Avoid editing settings.toml by hand.

Supporting files in ~/.config/noctalia/:

  • 90-greeter-sync.toml — enables Auto-Sync of the appearance with the login screen (msbos updates this file).
  • 91-widget-control-center.toml — control-center icon in the bar (rendered with the user's home path).
  • palettes/macOS.json — theme palette. msbos owns and updates it with an .msbos-bak backup; to use another one, create a new palette in palettes/ and point custom_palette in config.toml to it.

Default plugins enabled in settings.toml: tmelik/system-monitor (CPU/RAM in the bar capsule), raycursive/niri-displays (displays, on Super+P) and msbos/agent-usage (AI agent usage — OpenCode Go and GitHub Copilot — in panel tabs). Community plugins live in ~/.local/state/noctalia/plugins/; local plugins live in ~/.local/share/noctalia/plugins/ (the msbos ones — niri-displays, agent-usage and materialized — are copied from assets/noctalia/). The installer only copies a plugin when it does not exist yet.

Wallpaper

Noctalia owns the wallpaper. The default is /usr/share/msbos-walls/wp11280214-rx7-4k-wallpapers.jpg, set in settings.toml. Change it through Noctalia itself (Settings → Wallpaper) — the choice is persisted and Auto-Sync carries it to the login screen.

The msbos-wallpaper helper is a fallback for sessions without Noctalia: it uses swaybg and looks for the first image in alphabetical order in:

  1. ~/.config/msbos-walls/ (user, takes precedence)
  2. /usr/share/msbos-walls/ (system)

Accepted formats: PNG, JPG/JPEG and WebP. With no images, it uses the solid color #0B0B0D. The helper's spawn-at-startup is commented out in config.kdl precisely because Noctalia already handles the wallpaper.

App theme: Breeze Dark

msbos does not install a theme of its own. Apps use Breeze Dark, KDE's default dark theme, while Noctalia keeps its own look (it is not Qt/GTK).

  • Qt/KDE: ~/.config/kdeglobals gets ColorScheme=BreezeDark, widgetStyle=Breeze, breeze-dark icons and breeze_cursors; plasma-integration provides the Qt platform theme through QT_QPA_PLATFORMTHEME=kde.
  • GTK: ~/.config/gtk-3.0/settings.ini and gtk-4.0/settings.ini, the system default in /etc/dconf/db/local.d/00-msbos-dark and the user's gsettings set gtk-theme=Breeze, color-scheme=prefer-dark, icon-theme=breeze-dark and the breeze_cursors cursor.
  • Compatibility: pam-kwallet unlocks the KWallet vault at login and org.freedesktop.secrets is activated on demand over D-Bus (Electron/Tauri apps also read credentials); xdg-desktop-portal-kde and polkit-kde remain installed for KDE apps.

The installer only fills keys that are still empty. If you change the theme through System Settings, that choice is yours forever: msbos does not override it. Theme files owned by the project (GTK, dconf, profile.d) are updated with a backup.

Personal configurations

These files are installed only when they do not exist yet (install_file_once):

  • ~/.config/niri/config.kdl
  • ~/.config/noctalia/config.toml
  • ~/.config/alacritty/alacritty.toml
  • ~/.zshrc
  • ~/.config/zed/settings.json and the other files from assets/zed/
  • ~/.face (default avatar)
  • ~/.config/autostart/sealertauto.desktop and org.kde.xwaylandvideobridge.desktop

Re-running the installer does not overwrite these files. To return to the msbos default, delete the file and run the responsible step:

bash
rm ~/.config/niri/config.kdl
sudo bash scripts/50-configs.sh

Files owned by msbos — /etc/xdg/niri/config.kdl, theme assets, wallpapers, helpers, 90-greeter-sync.toml, 91-widget-control-center.toml and the palette — are updated with an .msbos-bak backup. settings.toml and plugins are only installed when absent.

Login screen (greetd + Noctalia Greeter)

greetd replaces Plasma Login Manager. Noctalia Greeter comes from the community Terra repository; with --no-greeter, greetd uses its default text greeter and Noctalia remains the session shell.

90-greeter-sync.toml enables Auto-Sync: changes to wallpaper, palette, theme and font are copied to the login screen. The installer enables passwordless sync through a Polkit rule restricted to the greeter action. On a reinstall (with Noctalia already running) it triggers a Sync Now at the end; on a clean install, the msbos-greeter-sync autostart does the first sync at login and writes the ~/.local/state/msbos/greeter-sync.done marker.

To repeat it manually:

bash
noctalia msg greeter-sync

If the wallpaper does not appear at login, check /var/lib/noctalia-greeter/sync.toml and the session shell in /etc/shells (pkexec requires the shell to be listed). More details in Troubleshooting.

Plasma shell removal

On a Fedora KDE base, the installer schedules the Plasma shell removal for the next boot, before login, through msbos-remove-plasma.service. It does not happen in the live session because the plasmalogin/plasma-* scriptlets touch systemd services and would kill the session in the middle of the dnf transaction.

The shell removal includes plasma-desktop, plasma-workspace, plasma-login-manager and plasma-setup; an installed plasma-welcome stays available and can be opened manually. The /etc/xdg/plasma-welcomerc config disables only the post-update news page, not the app.

All already-installed plasma-discover* packages—including the Discover store, notifier and backends—are kept and marked as user-installed, as is PackageKit when present; msbos does not install missing Discover packages. Discover notifications and updates remain available. Updates can also be done manually through DNF. The other selected KDE apps (Dolphin, Konsole, Kate/KWrite, Okular, Gwenview, Spectacle, Dragon, Elisa…) and the packages that keep KDE styling and portals working (plasma-integration, plasma-breeze, plasma-systemsettings, polkit-kde, xdg-desktop-portal-kde, pam-kwallet, kde-gtk-config, konsole) are kept. Removal uses --no-autoremove to keep the shell's dependencies; in particular plasma-workspace-libs, which provides the Users module of System Settings (kcm_users). msbos installs a Users launcher shortcut (~/.local/share/applications/msbos-usuarios.desktop) to open the module directly.

To follow it:

bash
systemctl status msbos-remove-plasma
journalctl -u msbos-remove-plasma -n 50

If removal fails (for example, no network at boot), the service stays enabled and tries again on the next boot. With --skip-remove, the Plasma shell remains installed, but login already goes to greetd/niri.

Updates

msbos does not install automatic updates; dnf-automatic is disabled on purpose. The Discover store, notifier and notifications remain available. Update manually through Discover or DNF when you want:

bash
sudo dnf upgrade --refresh
sudo reboot   # required for kernel, driver and initramfs

Firmware updates are manual too: if the Discover store and device support are available, use its firmware page; alternatively, use fwupdmgr from the command line:

bash
sudo fwupdmgr refresh
sudo fwupdmgr update

Re-running the installer is also safe and idempotent:

bash
sudo ./install.sh

It reapplies whatever is missing, preserves your personal configs and updates the files owned by the project (with backup). Zed and OpenCode update themselves through their official installers; lazydocker can be reinstalled by the 20-stack.sh step.
